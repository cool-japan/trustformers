## Development guidelines

- **Dependencies**: prefer `workspace = true` for every member dependency; `trustformers-serve` currently carries the largest count of literal version pins of any member (not audited pin-by-pin this pass — see P1). New dependencies must be pure Rust in default features; FFI dependencies (e.g. `mecab`, used optionally for Japanese/Korean tokenization) are feature-gated and never in `default`.
- **Code quality**: no `.unwrap()`/`.expect()` outside tests; snake_case naming; files under 2000 lines (see P1 File-size policy for current exceptions); zero-warning `clippy -D warnings` in the area you touch.
- **Testing**: every behavioral fix needs a regression test that would fail against the old code (this pattern is now well-established across the codebase — see "Recently resolved" above for examples). Tests use `std::env::temp_dir()`, never a hardcoded path. No network access in tests; local mock servers are fine.
- **Banned crates**: openblas→oxiblas, bincode→oxicode, rustfft→oxifft, rusqlite→oxisql-sqlite-compat, zip/flate2/zstd/bzip2/lz4/tar/snap/brotli/miniz_oxide→oxiarc-\*, most `-sys` FFI crates→the matching cool-japan/oxi\* crate. Enforced by `deny.toml`'s `[bans]` table; run `cargo deny check bans` before finishing any dependency change.
